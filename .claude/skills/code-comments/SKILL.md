# 주석 기준

**기본값은 주석을 쓰지 않는 것이다.** 코드가 못 하는 말만 남긴다.

## 쓰지 마라

코드를 한국어로 번역한 것. 이름만 봐도 아는 것.

```ts
// ✗ 판과 판 사이의 간격(초).
const PANEL_STAGGER = 0.08;

// ✗ 썸네일을 칸에 어떻게 앉힐지. 기본은 cover.
imageFit?: "cover" | "contain";

// ✗ 그려지기 전에 0 으로 만든다.
scale.setScalar(0);
```

상수·prop·스타일 선언마다 한 줄씩 붙이지 마라. 타입과 이름이 이미 그 일을 한다.
JSDoc 을 문단으로 늘리지 마라. 한 줄로 안 되면 대개 쓸 필요가 없는 말이다.

## 써라

다음 사람이 **코드를 지우거나 되돌리려 할 때 막아 줄 말**만.

**1. 재 본 값과 그 출처**

```ts
// 채색 영역 경계로 옮겼다. 가로 ×0.405, 세로 ×0.981.
export const CLOSE_ZONE_UV = { garden: [0.5159, 0.2005], ... };
```

**2. 뻔한 쪽을 왜 안 썼는지**

```ts
// MeshTransmissionMaterial 은 인스턴스마다 배경을 다시 렌더한다.
// 판을 열 몇 장 띄우는 구성이라 그 비용을 그대로 열 몇 배로 문다.
```

**3. 고치면 조용히 깨지는 것**

```scss
// fill 은 position:absolute 라 부모 크기에 기여하지 않는다.
// width:auto 로 두면 폭이 0 이 되어 그림이 통째로 사라진다.
width: 48px;
```

**4. 값이 서로 묶여 있다는 사실**

```ts
// 두 곳에 따로 적으면 조금만 어긋나도 판이 비뚤어진다.
elevation: FASTCAMPUS_ELEVATION,
```

## 판별법

지우고 나서 **다음 사람이 이 줄을 실수로 되돌릴 수 있나?**
아니라면 그 주석은 없어도 된다.

## 파일 머리 주석

컴포넌트 하나에 한 문단이면 충분하다. 그 조각이 **무엇을 위해 있는지**와
**건드리면 안 되는 전제** 하나 정도. 구현 순서를 서술하지 마라.
